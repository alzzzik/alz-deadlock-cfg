# QOLLOCK's test branch trims HUD work, not configs

QOLLOCK ("QOL Lock") is a HUD and quality-of-life mod, not a `gameinfo.gi`/`video.txt` FPS config. Its live test branch, `codex/customize-main`, holds **222 unreleased commits**. They make the mod's own HUD scripts do less work every frame, add a native magazine ring, and fix the ammo HUD for build 6801's new Nurse element. **The branch changes no engine settings, and nobody has published an FPS number for it** ([civo7/QOLLOCK](https://github.com/civo7/QOLLOCK); [branch commits](https://github.com/civo7/QOLLOCK/commits/codex/customize-main)). For alz, that means one thing: if you run QOLLOCK, measure it and update to the release built from this branch. Nothing from it belongs in your cfg files. On the cfg side, the honest answer is that **no line left in `gameinfo.gi` or `video.txt` is a proven, zero-visual FPS gain on a 5700X**. What's left falls into three groups: a handful of zero-visual changes you'd need to A/B yourself (the strongest being the Reflex sleep-timing switch, a few audio and particle lines that undo odd non-default values, and a texture-budget reset), about 50 dead or self-contradicting lines to clean out, and one big new particle lever (`r_particle_max_detail_level`, unblocked in build 6812) that does cost a little detail. Five earlier conclusions also need correcting. The most important one: the old experimental "−40 FPS" result can't be blamed on any config line, because its `video.txt` rendered roughly three times as many pixels as the setup it was compared against. Since nobody (Valve, OptiLock, OptimizationLock or ghempy53) has published a frame-time capture for any line here, every proposal below is a test plan, and your own matches are the only measurement that counts.

## QOLLOCK's branch is a cleanup of the mod's own HUD scripts

The project is QOLLOCK by civo, BreadRollius, bytenode and Predi_i. It ships as a VPK of Panorama layouts, styles and scripts through GitHub and GameBanana. Main is at **version 4.0.5**, last changed on 10-17, and its pinned Valve HUD files date from build 6779 ([README](https://github.com/civo7/QOLLOCK); [upstream.json](https://github.com/civo7/QOLLOCK/blob/main/upstream.json)). No branch is called "test" or "community". The branch that is moving is `codex/customize-main`: **222 commits ahead of main, about 78 of them by Predi-i between 10-21 and 10-25**, with the version still at 4.0.5, so it hasn't been released yet ([branch commits](https://github.com/civo7/QOLLOCK/commits/codex/customize-main)). None of QOLLOCK's 30 branches contains a `gameinfo`, `video.txt` or `autoexec` file ([repo tree](https://github.com/civo7/QOLLOCK)).

The branch is "cooking" three things. The first is **HUD script work reduction**: a dozen `perf:` commits such as "avoid recurring broad panel searches", "avoid redundant HUD color work" and "reuse parsed game clock text". Their shared rule is "Cache stable references rather than repeating `FindChildTraverse` every tick" and "A disabled feature should do zero or near-zero work" ([PERF_GUARDRAILS.md](https://github.com/civo7/QOLLOCK/blob/codex/customize-main/docs/PERF_GUARDRAILS.md)). Counting the source, the slow whole-HUD panel search drops from **695 call sites on main to 245 on the branch**, and logging calls drop from 308 to 183. That's less code, but it says nothing about runtime cost. The second is an **ammo HUD rework** that switches on Valve's own magazine ring through a new console command, `citadel_crosshair_enable_clip_status`. That is a real client-side `release` setting (default off) that only changes the crosshair ([VALIDATION.md](https://github.com/civo7/QOLLOCK/blob/codex/customize-main/docs/VALIDATION.md); [Valve convar dump, build 6821](https://github.com/SteamDatabase/GameTracking-Deadlock/blob/d251cf9d9a796061c90f58724230b7e17b97121b/DumpSource2/convars.txt)). The third is **catching up with Valve's builds 6790 and 6801**. Build 6801 added a `nurse_heal_icon` element to the gun HUD. The branch has it and main doesn't, so main 4.0.5 probably shows a mis-styled ammo panel when you play Nurse ([GameTracking 6801](https://github.com/SteamDatabase/GameTracking-Deadlock/commit/37f9aebdc62766aa13748f73309b9b8120549833)). That would be a visual bug, not an FPS problem.

The project is candid that **its tools don't measure FPS**. Its profiler numbers are "historical arbitrary weights … not measured milliseconds". Its in-game benchmark "excludes deferred layout, rendering, GPU work" and is "diagnostic rather than a clean FPS or frame-time benchmark". For real evidence it tells you to "compare game frame times with and without the mod on the same repeatable scene" ([PROFILING.md](https://github.com/civo7/QOLLOCK/blob/codex/customize-main/docs/PROFILING.md); [TESTING.md](https://github.com/civo7/QOLLOCK/blob/codex/customize-main/docs/TESTING.md)). The branch should still help a CPU-bound PC. HUD scripts run on the same main thread that limits you in team fights, so less script work there is the right kind of saving. Its size is unknown, though, and it only matters if QOLLOCK is installed. The repo doesn't say whether you run it. RESEARCH.md only mentions it as something not to clash with. If you do run it, there are three zero-visual steps. First, compare fight frame times with the QOLLOCK VPK on and off in DMM. Second, switch off every QOLLOCK feature you don't use, since disabled features are designed to stop polling. Third, update once a release built from this branch ships. Your cfg already suits it: `Game citadel/addons` is in SearchPaths, and its HUD-sensitive panorama lines are commented out as `//[mods]`.

That is the format that broke lighting for every pre-6801 cfg. As it stands, experimental can't be used for any test on build 6821.

## How to test so the numbers mean something

Every proposal below depends on your own A/B tests, so the method matters more than any single line. **Change one line at a time.** **Keep `video.txt` exactly the same between A and B** (back it up, and diff it after each session, because the in-game menu rewrites it). **Test in real matches, not Hideout, Sandbox or bot matches.** There the local server applies server-only and `replicated` lines that do nothing online, which makes the numbers look better than they are. Record with CapFrameX or PresentMon, or at least `cl_hud_telemetry_frametime_show 1`. Compare average FPS *and* 1% lows (the slowest 1% of frames, which is what fight stutter feels like) across two or three matches on each side. Two settings, `engine_low_latency_sleep_after_client_tick` and `r_citadel_disable_particle_lights`, are `release` convars, so you can flip them in the console mid-fight. Everything else needs a restart after editing `gameinfo.gi`. After each launch, type the convar name in the console to check that your value actually applied.

Two outside factors will spoil a test if you ignore them. **DMM 2.1+ turns performance configs on by default, and when it applies one it writes engine sections**. Update to 2.2.0, which also stops it rewriting `gameinfo.gi` on every launch. Then check that DMM treats your file as "My gameinfo.gi" and doesn't lay a catalog preset over it ([DMM 6f4891a](https://github.com/deadlock-mod-manager/deadlock-mod-manager/commit/6f4891a9602e2c2270e976ec73fa0a50cff3311a); [DMM 709ecbb](https://github.com/deadlock-mod-manager/deadlock-mod-manager/commit/709ecbb5f073ef35dfaa4f91d7cb141bc5bf61d8)). **Discard fights where Violet is painting.** Build 6819 lowered her Draw's minimum stroke distance from 40 to 15, and players report "drop FPS by 50-70% when looking at the drawing". That is a game-side cost no cfg line controls, and it will swamp any single-line difference ([GameTracking 6819](https://github.com/SteamDatabase/GameTracking-Deadlock/commit/17462b250a0ca80e7f80102f2c83cc3eecff5f12); [forum thread 179686](https://forums.playdeadlock.com/threads/violets-drawing-changes-tanked-the-fps.179686/)).

## Zero-visual proposals: a short list, all unmeasured

The cfg has very little zero-visual CPU headroom left. Valve already defaults every threading switch to on, its stock tail sets the parallel and spatial-partition lines, and the sun, cascaded shadows, SSAO, bloom and volumetric fog are already off ([Valve convar dump, build 6821](https://github.com/SteamDatabase/GameTracking-Deadlock/blob/d251cf9d9a796061c90f58724230b7e17b97121b/DumpSource2/convars.txt)). The 5700X has a single CCD and one core type, so `thread_pool_option` and core-affinity tricks can't help. The main thread is the limit, so only less work on it (particles, voices, HUD) or less waiting can help. What remains is listed below. `stable` and `alz` share an identical `gameinfo.gi` (only line 1 differs), so the gameinfo items apply to both, at the same line numbers. Evidence labels: **Measured** means numbers exist. **Claim** means a config author says it helps, without numbers. **Inference** means reasoned from Valve's own description or files.

### If you run QOLLOCK or another heavy script HUD mod

The QOLLOCK steps (measure the mod on and off, disable unused features, update to the branch's release) are the zero-visual items with the clearest mechanism for a CPU-bound PC. Leave the other engine-section edits alone. `VolumetricFog 0`, `CubemapFog 0` and `NonTexturedGradientFog 0` are part of your current look. The zeroed shadow atlases are what make every `csm_*` line redundant. And this PC has already measured engine-section changes as negative twice: round 1 gave "slightly less FPS", and OptiLock's sections gave 30-40 FPS less (`research/RESEARCH.md` §3).

### experimental: rebuild it before testing anything

Experimental needs one structural change before any proposal applies. **Rebase it on today's stable `gameinfo.gi`**, which has the 6801 lighting format, then add the cleanup above. After that, use it as a single-test slot: stable plus exactly one line, run with alz's `video.txt` held fixed. That makes the Z2-Z5 restart tests and the small-visual-cost tests below possible without touching stable. **Promote a line to stable only after it wins in real matches.** Don't carry over the round-2 bundle as a block. Several of its lines fail the zero-visual rule (`lb_precomputed_shadowmap_enable false`, `r_directional_lightmaps false`, `r_morphing_enabled false`, the panorama UI lines). Its shadow and CSM lines gain about 0, because the sun and cascades are already off in SceneSystem and `video.txt`. The sun-pass kill switch (`csm_max_visible_dist "0"` plus the `csm_cascade0..3_override_dist "0"` lines) is invisible but redundant for the same reason. Keep it only if you want belt and braces.

## Conclusion

This week's research moves the goal for your cfg. The question is no longer "which line gives FPS" but "which lines are you sure of". Almost every remaining `gameinfo.gi` lever is either already set, a no-op online, or a small visual trade. The one big new lever, particle detail level, arrived through a Valve flag change, not a community discovery. The next real gain will probably come the same way, so check each build's convar diff for newly unblocked or new `release` particle and render settings. Meanwhile the config scene has fewer measurements than ever: ghempy53 withdrew its numbers, OptiLock and OptimizationLock publish none, and QOLLOCK's own docs say its tools can't measure FPS.

That makes your own measuring setup the most valuable thing you can build. The −40 FPS episode shows why. One `video.txt` difference, DLSS 1.7x against DLAA, was enough to bury a whole round of config changes, and it went unnoticed for a week. A fixed `video.txt`, real matches, one line per test, 1% lows recorded and Violet fights thrown out would turn this report's three-dozen "claims" and "inferences" into facts for your PC. If QOLLOCK is in your mod list, the same method answers whether the HUD mod itself is your largest single fight-time cost, which no cfg line can fix.
